1. Ensemble Motivation & The Bias-Variance Problem

An ensemble combines multiple models to achieve better performance or robustness than any individual model. The jelly-bean jar analogy: the average of many independent noisy estimates converges on the true value better than any single estimate.

Motivation for ensembles stems from two limitations of individual models:

  • Overfitting (high variance): a deeply-grown decision tree fits training data perfectly but generalises poorly. Pruning reduces variance but also caps the accuracy ceiling.
  • Underfitting (high bias): simple models (shallow trees, stumps) are stable but systematically wrong in complex regions of feature space.
Bias-Variance decomposition: Total expected error = Bias² + Variance + Irreducible Noise.
Bias: systematic error due to wrong assumptions. Variance: sensitivity to training data fluctuations.
Bagging targets variance. Boosting targets bias.

Additional motivation: combining linear classifiers via smoothing — a weighted blend λ × (logistic regression) + (1−λ) × (complex model) inherits the global linear structure while preserving local non-linear adjustments.

2. Combination Rules & Ensemble Architecture Types

Algebraic Combination

Given two models with predicted probabilities, combine their scores using: minimum, maximum, or mean — then determine a new optimal cutoff on the combined score. Mean combination typically works well and produces stable probability estimates.

Voting

Majority voting: each model casts a class vote; majority class wins. Less sensitive to probability calibration. Weighted voting: assign vote weights based on each model's estimated accuracy (e.g., Model 4 gets 5 votes if it is much better). Determining weights is itself a learning problem (meta-learning).

Stacking (Wolpert, 1992)

  • Train Tier-1 classifiers on a bootstrap or jackknife subset of training data
  • Use Tier-1 predictions as input features for a Tier-2 meta-classifier (optionally combined with original features)
  • The meta-classifier learns to correct systematic errors of Tier-1 models
⚠ Stacking and mixture-of-experts both sacrifice interpretability and add production complexity. Use when performance gains justify the overhead.

Mixture of Experts (Jordan & Jacobs, 1991)

Multiple expert classifiers whose outputs are combined by a gating network trained via the Expectation-Maximization (EM) algorithm. The gating network learns which expert is most reliable for each region of feature space.

MethodHow it combinesWhen to prefer
Majority votingCount class votesModels with different strengths; no calibration needed
Mean probabilityAverage predicted probabilitiesWell-calibrated models; most common in practice
StackingMeta-classifier on top of Tier-1 outputsWhen Tier-1 models have complementary error patterns

3. Bagging & Random Forests

Bagging (Bootstrap AGGregating)

Bagging creates diversity by training each base model on a different bootstrap sample (sampled with replacement) from the training data. Models are trained independently (parallelisable) and combined by majority vote or averaged probability.

Sources of diversity in bagging:

  • Bootstrap resampling (different data subsets)
  • Subset of training instances (row sampling without replacement)
  • Subset of features (column sampling)
  • Using unstable learners (decision trees) — small changes in training data → very different trees → maximum diversity benefit

Out-of-Bag (OOB) Validation

Each bootstrap sample excludes ~37% of training instances. Those excluded instances can be used as a validation set for their respective tree. OOB error is a free, unbiased performance estimate — but does not replace a dedicated test set.

Majority vote: \(\hat p_{ens}(y=1|x) = \dfrac{|\{c \in C : p_c(y=1|x) \geq 0.5\}|}{|C|}\)

Averaged probability: \(\hat p_{ens}(y=1|x) = \dfrac{\sum_{c \in C} p_c(y=1|x)}{|C|}\)
Averaged probability and majority voting are nearly equivalent in practice — if the average probability exceeds 0.5, a majority of individual models almost always also vote positive.

Random Forests

Bagging of decision trees with one critical addition: at each split (not once per tree), only a random subset of M features is considered as split candidates. This breaks the correlation between trees — a single dominant feature cannot dominate every tree.

HyperparameterGuideline
Number of treesUse plenty — no risk of overfitting with more trees (validation performance plateaus)
Depth / pruningUsually no pruning needed; apply some stopping for speed only
Bootstrap size100% (sampling with replacement, not all instances appear); lower values if data is large
M (features per split)Classification: \(\lfloor\sqrt{N}\rfloor\); Regression: \(\max(\lfloor N/3\rfloor, 1)\); or tune via CV
Random forests capture interaction effects "for free" because many trees × random features = many different split combinations explored. No feature scaling needed. No explicit pruning needed. The trade-off: 100 trees are hard to explain vs. 1 tree.

Extra Randomized Trees (ExtraTrees): further randomizes split selection by also randomly drawing candidate split thresholds (not just candidate features), maximising variance reduction through diversity.

4. Boosting — Core Concept

Boosting builds an ensemble sequentially. Each new model focuses on correcting the errors made by the ensemble so far. Models cooperate rather than acting independently. This primarily reduces bias.

5. AdaBoost

AdaBoost (Adaptive Boosting) trains T weak learners sequentially. After each round, misclassified instances receive higher weight — forcing the next learner to focus on the hard cases. Each learner also receives a weight α_t reflecting its accuracy.

Algorithm Steps

  1. Initialise: uniform weights D₁(i) = 1/N for all i
  2. For t = 1 to T: train classifier h_t on weighted data
  3. Compute weighted error: \(\varepsilon_t = \sum_{i: y_i \neq h_t(x_i)} D_t(i)\)
  4. If ε_t > 0.5: stop early (learner is worse than chance)
  5. Compute learner weight: \(\alpha_t = \frac{1}{2}\ln\!\left(\frac{1-\varepsilon_t}{\varepsilon_t}\right)\)
  6. Update instance weights: \(D_{t+1}(i) = D_t(i) \cdot e^{-\alpha_t h_t(x_i) y_i}\) then normalise
  7. Final classifier: \(H(x) = \text{sign}\!\left(\sum_t \alpha_t h_t(x)\right)\)
Friedman et al. showed that AdaBoost is equivalent to additive logistic regression minimising an exponential loss function. This mathematical insight connects AdaBoost to a specific loss and motivated the generalisation to Gradient Boosting Machines.
⚠ If a weak learner's error ε_t > 0.5, it is worse than random — AdaBoost stops. This is why the weak learner must be weakly better than chance, not worse.

6. Gradient Boosting Machines (GBM) & XGBoost

Gradient Boosting — Core Idea

Instead of re-weighting instances (AdaBoost), GBM trains each new learner on the residuals (errors) of the current ensemble. This is equivalent to functional gradient descent: fitting the negative gradient of the loss function.
Ensemble update: \(F_{m+1}(x) = F_m(x) + h_m(x)\)

where \(h_m(x)\) is trained to predict \(y - F_m(x)\) (the residuals)

Connection: \(-\dfrac{\partial L_{MSE}}{\partial F} = \dfrac{2}{n}(y - F(x))\) — negative gradient = residuals for MSE

GBM generalises beyond MSE to any differentiable loss function:

Loss functionUse case
MSE: \(\frac{1}{n}\sum(y_i - \hat y_i)^2\)Regression
LogLoss: \(-\frac{1}{n}\sum[y_i\log p_i + (1-y_i)\log(1-p_i)]\)Binary classification
Multi-LogLoss: \(-\frac{1}{n}\sum_i\sum_j y_{ij}\log p_{ij}\)Multiclass classification

Extreme Gradient Boosting (XGBoost / LightGBM / CatBoost)

XGBoost extends GBM with two key improvements:

  1. Second-order gradients (Hessian): uses both the first and second partial derivatives of the loss, providing richer curvature information and faster convergence to the optimum
  2. L1/L2 regularisation on tree complexity: the objective function penalises the number of leaves and leaf weight magnitudes, directly preventing overfitting

XGBoost

  • Level-wise tree growth
  • Strong L1/L2 regularisation
  • Very stable and robust
  • Categorical: needs preprocessing
  • Good for mostly numerical tabular data

LightGBM

  • Leaf-wise tree growth (faster but riskier)
  • Histogram-based: very memory-efficient
  • Extremely fast on large datasets
  • Higher overfitting risk if untuned
  • Best when speed + large data matter

CatBoost

  • Symmetric (oblivious) trees
  • Native categorical feature handling
  • Ordered boosting (reduces target leakage)
  • Very strong defaults; minimal tuning
  • Excellent for small/medium data + many categoricals

DART (Dropouts + Trees)

  • Applies neural net dropout to boosted trees
  • Prevents early trees from dominating
  • Addresses the problem that late-added trees become negligible
  • Reports better results in some situations

XGBoost Advanced Features

Feature interaction constraints: restrict which features are allowed to interact in splits (e.g., feature A may only interact with B, not C). Prevents spurious interactions from being learned. Monotonic constraints: enforce that the model's prediction must increase/decrease monotonically with a specific feature — critical for regulated settings (e.g., higher credit risk must yield higher predicted default probability).

Level-wise vs. leaf-wise tree growth: XGBoost grows all nodes at a given depth level before going deeper (balanced trees). LightGBM grows the leaf with the highest loss reduction first (unbalanced but faster and often more accurate).

CatBoost's Ordered Boosting

Standard GBM calculates residuals using the same data points used to train the current model — causing prediction shift (target leakage within training). CatBoost uses a moving average of historical predictions in random permutations of training data, so each instance's residual is estimated only from models trained on instances that appeared before it in the permutation. This reduces bias in categorical encoding and gradient estimation.

⚠ Boosting can overfit — "overboosting" occurs when too many rounds are run without regularisation or early stopping. Monitor validation set performance over rounds and stop when it stops improving.

8. Deep Learning for Tabular Data

Tabular data differs fundamentally from images and text: features are heterogeneous (mix of numeric and categorical), datasets are often small/medium (10k–100k rows), and there is no inherent spatial or sequential structure to exploit.

Why GBMs Usually Win on Tabular Data

  • No strong spatial structure (unlike CNNs for images)
  • No natural sequential structure (unlike transformers for NLP)
  • Tree ensembles capture non-linear interactions easily with few samples
  • Gradient boosting consistently outperforms deep nets in honest benchmarks on tabular data

Standard Deep Learning Approaches for Tabular Data

MLPs (Multilayer Perceptrons): simple strong baseline. Numeric features: normalise. Categorical features: embeddings or one-hot encoding. Fast to set up (even in scikit-learn). But typically underperform GBMs.

Tabular-specific architectures: attempt to model feature interactions explicitly by treating each feature as a "token" and using attention mechanisms.

ArchitectureKey idea
TabNetSequential attention with sparsity — selects a subset of features at each step. Interpretable attention masks.
FT-TransformerFeature-wise attention: each feature is a token; transformer models cross-feature interactions.
SAINTRow + column attention: attends both to features within an instance and across instances.
NODE / DeepGBM hybridsNeural networks with tree-like decision function layers embedded in the architecture.
⚠ Despite architectural sophistication, tabular-specific deep learning methods rarely outperform well-tuned XGBoost/LightGBM in most practical benchmarks. The overhead (training time, tuning complexity, less interpretability) is substantial.

TabPFN — Prior-Data Fitted Networks

TabPFN brings the "foundation model" idea to tabular data. Instead of training per dataset, it is trained once on millions of synthetic tabular tasks and applied directly to new datasets at inference time — no hyperparameter tuning required.
  • Architecture: Transformer trained on synthetic tabular tasks
  • Learns Bayesian inference over tasks — approximates Bayesian model averaging
  • At inference: feed in your labelled training data as context; the model predicts directly
  • TabPFN v1: underperformed GBMs. TabPFN v2 / v2.5: often on par or better than GBMs for small/medium datasets
  • Limitation: >10k rows requires special handling (subsampling or approximation)
