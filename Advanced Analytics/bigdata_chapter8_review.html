8.1 Why Graphs?

Graphs capture relational structure that tabular feature vectors cannot express. Real-world networks include hyperlink graphs, email traffic, citation networks, financial transactions, social platforms (LinkedIn, Facebook, Twitter), and epidemiological contact maps.

Key insight: The same business problem (e.g., churn, fraud) can be formulated in many different ways depending on how the network is constructed. Network design choices directly affect analytical outcomes.

Applications: web community mining, fraud detection, terrorism suspicion scoring, product recommendations, churn detection, epidemic spread modeling.

Graphs are semi-structured: no direct feature-vector representation exists. Featurization requires non-trivial wrangling, and the network construction step itself must be driven by the intended analytical objective.

8.2 Graph Construction & Terminology

Core Concepts

ElementAlso CalledExample
NodeVertex, pointPerson, company, credit card, webpage
EdgeLink, arc, lineFriendship, transaction, co-authorship

Node Considerations

Homogeneous graphs: all nodes represent the same entity type.
Heterogeneous graphs: multiple node types (e.g., customers and products). Node features can include attributes like age, gender, address — or a single node weight.

Edge Considerations

  • Directionality: directed vs. undirected edges; self-edges; reciprocal edges.
  • Cardinality: binary vs. weighted; duplicated edges; hyperedges (involving >2 nodes).
  • Edge type: homogeneous vs. heterogeneous edge types (e.g., "friend" vs. "colleague").

Network Representation

Adjacency matrix (node × node): entry Aij = 1 (or weight) if edge (i,j) exists.
Incidence matrix (node × edge): maps nodes to the edges they participate in.
Both can provide structural insight without any predictive modeling.
Transformation to unipartite graphs: heterogeneous networks are often simplified. Techniques: binary projection, common-neighborhood weighting, Jaccard weighting.
Recency-based edge weights: more recent interactions receive higher weight, useful in dynamic networks.
Practical starting point (Oskarsdóttir 2018): begin with a non-directional, unweighted, binary, single-node-type graph. Add pseudo-edges to ensure sufficient density before introducing complexity.

Data Sources

  • Graph databases (though re-construction may still be needed)
  • Traditional flat / relational / transactional data

8.3 Graph Metrics & Centrality

Centrality measures identify important nodes — most influential, key infrastructure, super-spreaders.

MeasureIntuitionFormula / Key IdeaApplication
Degree centrality Local connectivity: number of edges deg(v) / (n−1) for normalized; in-degree vs. out-degree in directed graphs Identifies hubs, connectors, deal-makers
Closeness centrality Geographic proximity to all other nodes C(x) = (N−1) / Σ |geod(x,y)| High visibility; quick access to information
Betweenness centrality Frequency of lying on shortest paths Count of geodesics passing through node Gatekeepers; control over information flow
Eigenvector centrality / PageRank Influence weighted by neighbor importance Iterative: x = Ax / λ; PageRank adds teleportation Google web ranking; authority scoring
Geodesic path: the shortest path between two nodes (may use edge weights or unit weights).
Graph theoretic center: argminn∈N ( max { |geod(n,m)| : m∈N } ) — the node(s) with the smallest maximum distance to all others.
Degree ≠ Influence: a high-degree node connected mostly to low-degree nodes may have less real influence than a moderate-degree node connected to hubs. Eigenvector centrality captures this nuance.
Centrality values can be used as features in downstream predictive models, not just for exploratory visualization. Practical uses: blocking viral effects, targeting viral marketing, identifying physical infrastructure bottlenecks.

8.4 Community Mining

A community is a subgraph with dense internal edges and sparse external edges. Communities arise naturally in the web, telecom, academic, and social networks.

Key Algorithms

Girvan-Newman: divisive approach. Iteratively remove the edge with the highest betweenness centrality, recalculate betweenness after each removal. Computationally expensive: O(m²n) on sparse graphs.
Min-cut variants:
  • Min cut: minimize total weight of cut edges.
  • Min-max cut: balances cut sizes between communities.
  • Min ratio cut: accounts for within-community edge density.
Louvain algorithm (Blondel et al.): greedy modularity optimization.
  1. Initialize: each node is its own community.
  2. Move each node to the neighbor-community that maximizes modularity gain; repeat until no improvement.
  3. Collapse communities into supernodes; rebuild graph. Repeat until convergence.
Modularity Q measures relative internal vs. external edge density.

Cliques and k-cores

Clique: every node connected to every other node.
Maximal clique: not a subset of any larger clique. (Finding all maximal cliques is NP-hard.)
k-core: maximal subgraph where every node has at least k neighbors within the subgraph — a computationally tractable near-clique.
Most community mining algorithms assume the full network structure is known. Detecting overlapping communities is significantly harder. Always question what the found communities mean substantively.

Applications: targeted/viral marketing, churn prevention, segmentation analysis, community labels as additional features for prediction.

8.5 Featurization & Network-Based Inference

Two Paradigms

ApproachDescriptionExamples
Network learningDirectly use network structure for inferenceRelational Neighbor Classifier, Label Propagation, Personalized PageRank
FeaturizationExtract features from the graph for any downstream modelCentrality metrics, community labels, egonet features, embedding vectors

Homophily

Homophily ("birds of a feather"): connected nodes tend to share the same label. Formally, intra-group edges dominate inter-group edges.

Examples: fraudsters cluster and share resources; churners influence neighbors to churn; income-similar people call each other.
Basis for the guilt-by-association inference principle.
Homophily is often assumed but not always valid. Always verify empirically whether the label distribution among neighbors deviates from random.

Relational Learners

Markov property assumption: a node's outcome depends only on its first-order neighbors.

Relational Neighbor Classifier (RNC): estimates P(Y=class | node) by counting the class labels of direct neighbors. Simple but a useful baseline.

Propagation-Based Methods

MethodKey Idea
Personalized PageRankBiased random walk: teleport probability α directed toward known positive nodes (seeds). Resulting scores reflect proximity to positives in the graph.
Label Propagation (Zhu & Ghahramani, 2002)Iteratively propagate soft labels from labeled nodes to neighbors; converges to a smooth labeling consistent with the graph structure.
Label SpreadingVariant with regularization; allows labeled nodes to partially change their labels. More robust to noisy labels.

Relational Logistic Regression (Lu & Getoor, 2003)

Combines local attributes (age, income, RFM) with network attributes:
  • Mode-link: most frequent class label among neighbors.
  • Count-link: frequency of each class label among neighbors.
  • Binary-link: binary indicator for presence of each class among neighbors.
Any classifier can replace logistic regression. Add centrality values and propagation scores as additional features.

Featurization Best Practices

Keep the base graph simple. Add domain-driven features at the egonet level. Include Personalized PageRank as a global network signal. Use community labels as additional features. Combine with standard tabular features in any off-the-shelf classifier.

8.6 Validation — Why It's Hard with Networks

Core problem: standard train/test splitting is insufficient. Even if features are computed separately for train and test, the underlying graph is shared — introducing structural data leakage. Node labels and graph structure both change over time.

Sources of Leakage

  • Network features computed on the whole graph are contaminated by test-set labels.
  • Personalized PageRank explicitly uses label information; centrality metrics do not — but they still encode test-set topology.
  • Transductive GNN evaluation: masked nodes still message-pass to training nodes.

Mitigation Strategies

  • Use temporal splits where possible (train on past, test on future); ensure a large enough time gap.
  • Randomly censor positive labels in the training graph during feature generation.
  • Test at multiple time points to ensure robustness.
  • Domain-driven features based on neighbor attributes (not labels) are less problematic.
Shchur et al. (2018): "existing evaluation strategies for GNN models have serious shortcomings." No strategy is perfect; large overlap between train and test network structure remains. At deployment time, the model needs the up-to-date state of the network — a stringent data requirement.

8.7 Graph Neural Networks

From Random Walks to Embeddings

Random walk: a process that starts at a vertex and moves to a uniformly (or proportionally in weighted graphs) chosen neighbor at each step. Foundation for DeepWalk and Node2vec.
MethodIdeaLimitation
DeepWalk (Perozzi et al. 2014)Random walks + skip-gram (Word2Vec) to learn node embeddingsNo node/edge features; no generalization to unseen nodes
Node2vec (Grover & Leskovec 2016)Biased 2nd-order random walk with parameters p, q: BFS-like (community) vs. DFS-like (structural) embeddingsSame as DeepWalk; encoder parameters grow linearly with nodes
Drawbacks of random-walk embeddings: no parameter sharing across nodes; cannot incorporate node/edge features; cannot generalize to dynamic graphs (new nodes at inference time).

GNN Fundamentals

Graph input types: node features, edge features, global features, connectivity.
Connectivity representation: adjacency matrix (sparse; not permutation-invariant) vs. adjacency list (memory-efficient tuples (i,j) describing edge k between nodes i and j).

Core GNN Operations

Pooling: aggregate embeddings from one type (e.g., edges) and pass to another type (e.g., nodes) for prediction. Analogous to global average pooling in CNNs for graph-level tasks.
Message Passing (generic form):
x_i^k = γ^k( x_i^(k-1), AGG_{j∈N(i)} φ^k( x_i^(k-1), x_j^(k-1), e_{j,i} ) )
φ = gather/message function  |  AGG = aggregator (sum or mean)  |  γ = update function (MLP)
Message passing is equivalent to convolution in irregular domains. Stacking k layers expands the effective "receptive field" to k-hop neighborhoods.

Spatial GNN Architectures

ArchitectureKey MechanismReference
GCN Symmetric degree-normalized aggregation: x_i' = Θᵀ Σ_{j∈N(i)∪{i}} e_{j,i} x_j / √(d̂_j · d̂_i) Kipf & Welling, 2016
GraphSAGE Sample neighbors + aggregate (mean/LSTM/max pooling); inductive — handles new nodes Hamilton et al., 2017
GAT Attention-weighted neighbor aggregation; learns which neighbors matter most Veličković et al., 2017

Spectral vs. Spatial

DimensionSpatialSpectral
BasisNeighborhood structureSpectral graph theory / Laplacian
ConvolutionMessage passing between neighborsPolynomial filter on graph Laplacian
Information scopeLocal around a nodeGlobal graph information

Learning Tasks & Inductive vs. Transductive

Node-level tasks: classification, regression, clustering per node.
Edge-level tasks: link prediction, edge label classification.
Graph-level tasks: graph classification or topology learning.
Transductive learning: train and test on the same graph; mask loss for test nodes but they still message-pass → structural leakage. Widely used in practice but flawed.

Inductive learning: train on one graph, test on separate unseen graphs/nodes. Requires GNN units independent of node/edge count. Splitting one graph into train/test is non-trivial: cutting edges removes information.

8.9 Graph Databases & NoSQL

Why Not RDBMS?

Relational databases require formal schema, guarantee ACID consistency, but struggle with: highly dynamic data, flexible structures, massive horizontal scalability, and traversal-heavy queries (e.g., friend-of-a-friend).

NoSQL Landscape

TypeModelExamples
Key-valueHash mapRedis, DynamoDB
DocumentJSON/BSON documentsMongoDB, CouchDB
Column-familyWide columnsCassandra, HBase
GraphNodes + typed edges + propertiesNeo4j, Memgraph, EdgeDB
Time seriesTimestamped recordsInfluxDB, TimescaleDB, Kdb+
GeospatialSpatial objectsPostgreSQL+PostGIS, ESRI
Eventual consistency: NoSQL databases often sacrifice continuous consistency for availability and partition tolerance. Data replicas will converge, but may be transiently inconsistent. This is the trade-off encoded in the CAP theorem.

Cypher Query Language (Neo4j)

Declarative, pattern-matching language for graph databases. Nodes written as (n:Label); directed edges as -[:RELATION]->.
Basic match:
MATCH (b:Book) RETURN b ORDER BY b.price DESC LIMIT 20;
Multi-hop traversal (friend-of-a-friend):
MATCH (b:Book)-[:IN_GENRE]->(:Genre)-[:PARENT*0..]-(tg:Genre) WHERE tg.name = "Programming" RETURN b.title;
The *0.. wildcard traverses hierarchies of arbitrary depth — trivially in Cypher, complex in SQL even with recursive CTEs.
Graph databases as hyper-relational databases: JOIN tables are replaced by semantically meaningful, traversable relationships. Many-to-many relations are first-class citizens, not cross-tables.
Neo4j is optimized for OLTP, not OLAP. For analytical workloads, use the Graph Data Science Library (GDS). Memgraph offers MAGE for graph algorithms. Early NoSQL adopters (Digg, Twitter, HealthCare.gov) experienced serious issues with lack of consistency and complex queries — "NoSQL" was not always the right choice.

Short Answer 1
Explain why network construction choices matter as much as analytical technique choices, and give a concrete example where two different network constructions of the same data lead to qualitatively different conclusions.
Model Answer: Network construction is a design decision that encodes domain assumptions: which entities are nodes, what constitutes a link, whether edges are directed, weighted, or binary. These choices determine what structure the algorithm sees. For example, in a telecom churn scenario, constructing an undirected binary graph (any shared call = edge) versus a directed recency-weighted graph (recent calls carry higher weight, direction captures who initiates contact) will produce different community structures and different centrality rankings. A churner who initiated most calls may appear differently in degree and betweenness centrality depending on whether directionality is captured. The wrong construction can obscure the homophily signal or mis-identify hubs.

Follow-ups: How would you validate that one network construction is better suited to your objective? What is the relationship between network construction and feature leakage in validation?
Short Answer 2
Compare betweenness centrality and closeness centrality. In which real-world scenarios would you prefer each, and what are their computational limitations for large graphs?
Model Answer: Betweenness centrality counts how often a node appears on shortest paths between all other pairs — it identifies gatekeepers who control information or resource flow (e.g., a consultant bridging departments, a router in a network). Closeness centrality measures how quickly a node can reach all others (inverse of average geodesic distance) — it identifies efficient broadcasters or early adopters of information. In epidemic modeling, closeness identifies who spreads disease fastest; in organizational network analysis, betweenness identifies key brokers whose removal fragments the network. Both require computing all-pairs shortest paths: O(V·E) with BFS for unweighted graphs, making them expensive for very large networks (millions of nodes). Approximation algorithms (e.g., Brandes for betweenness) mitigate this.

Follow-ups: How do you handle disconnected graphs when computing closeness? Can betweenness be computed for edges and why would that be useful?
Short Answer 3
Explain the concept of homophily and its role in network-based inference for fraud detection. Under what conditions might homophily not hold, and what are the consequences for your model?
Model Answer: Homophily ("birds of a feather") means that connected nodes are more likely to share the same class label than expected by random chance. In fraud detection, fraudsters tend to cluster — they share merchants, use the same resources, or are part of organized rings — so edges between fraudsters are more common than edges between fraudsters and legitimate users. This enables "guilt-by-association": a node's neighbors' labels are informative about its own label. Homophily may NOT hold if fraudsters deliberately target legitimate users (e.g., phishing), if the graph is a bipartite customer-merchant graph where no direct fraudster-to-fraudster edges exist, or if the graph topology is dominated by random noise. When homophily is absent, propagation-based methods and relational neighbor classifiers will perform at or below chance and may actually introduce negative transfer. Always empirically verify homophily by measuring the fraction of same-class edges vs. a random baseline.

Follow-ups: How would you test for homophily statistically? What if there is heterophily (connected nodes tend to have different labels)?
Short Answer 4
Describe the message-passing paradigm in GNNs. How does it relate to convolution? What are the roles of the message function φ, the aggregator AGG, and the update function γ?
Model Answer: Message passing updates a node's embedding by (1) generating messages from each neighbor using a message function φ(x_i, x_j, e_{ij}), (2) aggregating all incoming messages with AGG (typically sum or mean — must be permutation-invariant since neighbor order is arbitrary), and (3) updating the node's own representation with an update function γ (typically an MLP) that combines the aggregated messages with the node's current embedding. This mirrors convolution in that it applies a shared, local operation (a "filter") over a neighborhood — but on irregular graph topology rather than a regular grid. The connection to convolution is formal: the neighborhood-weighted sum in GCN is equivalent to a convolution in the graph spectral domain with a polynomial filter. Stacking k message-passing layers effectively gives each node access to its k-hop neighborhood, analogous to a CNN with a large receptive field.

Follow-ups: Why must the aggregator be permutation-invariant? What happens to the receptive field as you add more GNN layers? What is over-smoothing?
Short Answer 5
Explain the difference between transductive and inductive GNN learning. What are the advantages and pitfalls of each approach in a real business deployment scenario?
Model Answer: In transductive learning, the model is trained and evaluated on the same graph — test nodes are present during training but their labels are masked out of the loss function. This is simple but introduces leakage: masked test nodes still message-pass information to training nodes, meaning the model has indirectly "seen" the test topology. In inductive learning, the model is trained on one set of graphs/nodes and evaluated on entirely new, unseen ones. This is more realistic for deployment (new customers join the network) but requires GNN units whose operations are independent of graph size, and splitting a single graph into train/test is non-trivial — cutting edges removes structural information. In business practice, temporal splits (train on historical graph, test on future graph) are the most defensible approach, assuming a sufficient time gap so there is minimal overlap between train and test structural features.

Follow-ups: Which published GNN models are inductive by design? Why did Shchur et al. (2018) criticize standard GNN evaluation? How does temporal splitting relate to the concept of data leakage in standard ML?
Short Answer 6
What is modularity in the context of community mining, and why is maximizing modularity not always the right objective? Discuss at least one known failure mode.
Model Answer: Modularity Q measures the fraction of edges within communities minus the expected fraction if edges were placed randomly (preserving degree distribution). Maximizing Q finds partitions with denser intra-community edges than expected by chance. However, modularity maximization has a well-known resolution limit: for large networks with many small communities, modularity optimization will merge small communities into larger ones even if they are internally well-connected, because small communities contribute too little to Q to be individually detectable. Additionally, Q has a "plateau" problem: many partitions can achieve similar Q values, making the solution non-unique. Modularity also depends on the choice of null model and can be sensitive to the network's density. In practice, multiple community detection runs with different algorithms and parameters, followed by stability analysis, gives more reliable results than blindly maximizing modularity.

Follow-ups: How does the Louvain algorithm avoid some of these pitfalls? What is the Leiden algorithm, and how does it improve on Louvain?
Short Answer 7
Compare graph databases (e.g., Neo4j) and relational databases for a many-to-many relationship query with multi-level hierarchy traversal. When does the graph database approach offer a fundamental — not just ergonomic — advantage?
Model Answer: In a relational database, a many-to-many relationship between, say, products and categories requires a junction table, and traversing a hierarchical category tree (e.g., "all products in Programming or any of its subcategories") requires recursive CTEs or repeated self-joins — expensive and hard to express. In Neo4j/Cypher, this is a single MATCH clause with a variable-length path pattern like [:PARENT*0..] — the database engine traverses graph edges natively. The fundamental advantage is in traversal-heavy, relationship-centric queries where the depth is unknown in advance: friend-of-a-friend queries, shortest path, reachability. These are O(depth) in a graph database using adjacency-list-based index-free adjacency, but can require O(n·JOIN) operations in SQL. For simple lookups or aggregate analytics (summing sales by region), relational databases with indexes are equally fast or faster. The right choice depends on query patterns, not just data structure.

Follow-ups: What is "index-free adjacency" in Neo4j? When would you use GraphQL vs. Cypher? What trade-offs does Neo4j make to achieve traversal speed?
Short Answer 8
Explain Personalized PageRank (PPR) and how it differs from standard PageRank. How would you use PPR to score fraud risk for unlabeled nodes, and what hyperparameter governs the spread of the signal?
Model Answer: Standard PageRank models a random walker who, at each step, either follows a random edge (probability 1−α) or teleports to a uniformly random node (probability α). Personalized PageRank replaces the uniform teleport distribution with a personalized one — for fraud detection, the teleport distribution is concentrated on known fraud seeds (confirmed fraudsters). The resulting stationary distribution assigns higher scores to nodes that are topologically close to the seeds in the graph. The hyperparameter α (teleport probability) controls locality: high α keeps scores tightly concentrated near seeds; low α allows the signal to diffuse broadly. In practice, PPR scores for each unlabeled node become a real-valued feature in a downstream classifier. The approach is semi-supervised: it uses the few labeled positives to spread a signal across the graph consistent with the homophily assumption.

Follow-ups: How does PPR relate to label propagation? What computational tricks allow PPR to scale to billion-node graphs? How would you set α in practice?
Short Answer 9
You are designing a validation strategy for a GNN-based fraud detection model on a single large transaction graph. Walk through the main challenges and your proposed approach.
Model Answer: The main challenges are: (1) Standard random train/test split cuts edges, destroying topology and leaking structural information; (2) Transductive GNN evaluation leaks test-node topology through message passing during training; (3) Network features (PPR, community labels) computed on the full graph incorporate test labels; (4) Node labels change over time, creating temporal inconsistency. Proposed approach: use a temporal split — train on the graph state at time T₁, validate at T₂, test at T₃, ensuring sufficient gaps (e.g., months) between windows to minimize structural overlap. For network features, compute them using only the training-window graph. For the GNN itself, use a transductive setup with temporal node masking, but acknowledge and report the residual leakage. Additionally, randomly censor a fraction of known positive labels during feature computation as a sensitivity check. Test at multiple time points to assess robustness. Report AUC with confidence intervals across multiple time windows, not a single holdout.

Short Answer 10
Why did the "NoSQL movement" not entirely deliver on its promises, and how did the industry respond? What does this tell us about the trade-offs at the heart of distributed database design?
Model Answer: Early NoSQL systems sacrificed consistency (ACID guarantees) and query expressiveness for horizontal scalability and flexible schemas. In practice, many applications (healthcare.gov, early Digg, Twitter) found that eventual consistency led to data corruption bugs, and that MapReduce interfaces were harder to use than SQL for complex analytics. The industry responded with two movements: (1) NoSQL vendors adding stronger consistency models and better query languages (moving toward SQL-like capabilities), and (2) the NewSQL movement — systems like CockroachDB, Google Spanner, and YugabyteDB that achieve horizontal scalability while maintaining ACID guarantees. This convergence illustrates the CAP theorem: distributed systems must choose between consistency, availability, and partition tolerance — not all three simultaneously. The key insight is that the optimal trade-off depends on the use case: financial transactions require consistency; social media feeds tolerate eventual consistency. There is no universally superior architecture.
