1. Text as Data — The Featurization Challenge

Goal: Convert a collection of free-form text documents (a corpus) into numeric feature vectors that machine learning algorithms can consume. Each document is one instance; each word (token) is a potential feature dimension.

Why Text is Hard

  • No natural feature-vector representation — text is variable length and unstructured.
  • Linguistic structure: word order, negations, sarcasm, context, ambiguity.
  • Dirty data: spelling errors, abbreviations, homographs, informal grammar.
  • High dimensionality: a typical vocabulary runs into hundreds of thousands of words.

Bag of Words (BoW)

Each document is represented by a binary vector indicating which words from the vocabulary appear. Word order and grammar are completely ignored.
Example:
Vocabulary: [this, is, an, a, example, second]
"This is an example" → [1, 1, 1, 0, 1, 0]
"This is a second example" → [1, 1, 0, 1, 1, 1]

Text Preprocessing Pipeline

StepPurposeExample
Case normalisationUnify surface formsRunning → running
Stop-word removalRemove very common, uninformative wordsRemove "the", "and", "of"
Stemming (Porter)Strip suffixes to root formjumped, jumping → jump
LemmatisationContext-aware normalisation to dictionary formbetter → good; flies → fly
PoS taggingTag each token with grammatical roleApple (PROPN), is (VERB)
⚠ Stemming is fast but crude (suffix-stripping). Lemmatisation is more accurate but requires a parser and dictionary. Choose based on downstream task requirements.

N-gram Sequences

To capture word order, use n-grams: sequences of n adjacent tokens. Bi-grams (n=2) are most common. "The quick brown fox" → bi-grams: {quick_brown, brown_fox}. Greatly increases feature dimensionality.

2. TF-IDF and BM25

Term Frequency (TF)

\[\text{TF}(t_i, d) = \frac{f(t_i, d)}{|d|}\] Number of occurrences of term \(t_i\) in document \(d\), divided by total document length.

Inverse Document Frequency (IDF)

\[\text{IDF}(t_i) = 1 + \log\!\left(\frac{|c|}{|\{d \in c : t_i \in d\}|}\right)\] Penalises terms that appear in many documents (common → less informative). Higher IDF = rarer term.

TF-IDF

\[\text{TFIDF}(t_i, d) = \text{TF}(t_i, d) \times \text{IDF}(t_i)\] Each document becomes a weight vector \(d = [w_1, w_2, \ldots, w_m]\) where \(w_i = \text{TFIDF}(t_i, d)\).
TF-IDF rewards terms frequent in a document but penalises terms that are frequent across the whole corpus. This surfaces discriminative terms.

BM25 (Okapi Best Matching 25)

\[\text{BM25}(q,d) = \sum_{i=1}^{n} \text{IDF}(q_i) \cdot \frac{f(q_i, d)\cdot(k_1+1)}{f(q_i, d) + k_1\!\left(1 - b + b\cdot\frac{|d|}{\text{avgdl}}\right)}\] Typical values: \(k_1 \in [1.2, 2.0]\), \(b = 0.75\).
FeatureTF-IDFBM25
Term frequency saturationLinear — repeated terms scale unboundedlySaturates — 100× a word ≠ 100× more important
Document length normalisationDivision by |d|Parametric via \(b\) — more flexible
Typical useFeature matrix for MLQuery-document scoring, retrieval
PerformanceStrong baselineOften better than TF-IDF; sometimes beats embeddings

Dealing with High Dimensionality

  • Feature selection (chi-squared, mutual information)
  • Hashing trick: collapse vocab to n hashed features
  • Dimensionality reduction: t-SNE, UMAP, PCA
  • Scalable models: Naive Bayes, linear SVM (proven effective for text)

3. Classical NLP Tasks

NLP uses ML and statistical methods to learn language from data — capturing context, negations, and ambiguity that bag-of-words misses. These tasks are now predominantly solved by deep learning.

Sentiment AnalysisDetect polarity or emotion in text"This camera sucks" = negative; "vacuum cleaner sucks" = positive

4. Representational Learning & Word Embeddings

From Sparse to Dense Representations

BoW and TF-IDF produce very high-dimensional, sparse vectors (one dimension per vocabulary word). Word embeddings map each word to a dense, low-dimensional continuous vector — typically 50–1000 dimensions — that captures semantic meaning.

Distance metrics (cosine, Euclidean) in embedding space approximate semantic similarity. The famous analogy: [king] − [man] + [woman] ≈ [queen] demonstrates that arithmetic in embedding space reflects linguistic relationships.

What Makes a Good Embedding?

  • Semantically similar words cluster together in vector space.
  • Analogical relationships encoded as consistent vector offsets (male-female, country-capital, verb tense).
  • Reusable across downstream tasks (transfer learning).
  • Dense and low-dimensional — reduces overfitting vs. sparse BoW.

Embedding Bias

⚠ Embeddings learned from real-world text inherit societal biases. The Word-Embedding Association Test (WEAT) found that "man" associates with "programmer" and "woman" with "homemaker" — reflecting biases in training corpora, not objective truth. Always audit embeddings before deployment in sensitive contexts.

Generalised Embeddings

The embedding principle extends beyond text: categorical embeddings map high-cardinality variables (e.g., day of week, product IDs) to continuous vectors. A simple NN with input → embedding → outcome learns task-relevant representations. Recommended embedding size: approximately \(1.6 \cdot |categories|^{0.56}\).

Similarly, node2vec applies the same idea to graph nodes, doc2vec to entire documents, and listing2vec (Airbnb) to product listings.

5. word2vec

Released by Google in 2013 (Mikolov et al.). Core idea: a word is defined by its context. The model learns embeddings by training on a self-supervised task — predicting words from context or context from words. After training, the network is discarded and only the weight matrix is kept as the embedding table.

Two Learning Methods

CBOW (Continuous Bag-of-Words)CSG (Continuous Skip-Gram)
InputContext words (surrounding tokens)Focus word (centre token)
Prediction targetFocus wordContext words
Hidden activationWeighted average of context embeddingsPass-through (no activation)
Word order sensitivityNone — context treated as bagNone — context words fed one-by-one
Data efficiencyBetter — averaging provides smoothingMore training data required
Embedding qualityGood for frequent wordsBetter quality; captures rare words well

Architecture Details (CBOW)

Input: C context words, each one-hot encoded with vocabulary size V.
Weight matrix W (V×N): each row is the embedding for one word.
Hidden layer: average of C context embeddings → N-dimensional vector.
Output: softmax over V vocabulary → predicts focus word.
After training: W is the embedding lookup table.

Practical Optimisations

  • Negative sampling: Instead of updating all V output weights, only update a small number of "negative" (non-target) examples — much faster.
  • Subsampling: Frequent words (e.g., "the") are subsampled during training — they contribute less information per occurrence.
  • Random context window: Window size is sampled randomly per instance.
  • Visualisation: High-dimensional embeddings (e.g., 1000-d) projected to 2D via PCA or t-SNE for inspection.

6. Recurrent Neural Networks (RNNs)

RNNs process sequential data by maintaining a hidden state — a compact summary of all past inputs. The same weights are applied at every time step (weight sharing across time). This allows the model to handle sequences of variable length.

Core Equations

Hidden state: \(a^{\langle t \rangle} = \tanh(W_{ax} x^{\langle t \rangle} + W_{aa} a^{\langle t-1 \rangle} + b_a)\)

Output: \(\hat{y}^{\langle t \rangle} = \text{softmax}(W_{ya} a^{\langle t \rangle} + b_y)\)

Key Properties

PropertyDetail
Weight sharingSame W applied at every time step — model size does not grow with sequence length
State dependencyState at t depends on state at t−1, which depends on t−2, etc. — implicit memory of full history
Training algorithmBackpropagation Through Time (BPTT) — unrolls the RNN in time and applies standard backprop
Practical limitationVanishing/exploding gradients make it hard to learn long-range dependencies in practice
⚠ RNN training is hard: all challenges of deep networks (vanishing gradients, sensitivity to initialisation) are compounded by the non-linear dynamical system nature — weight changes can destabilise the system entirely.

Bidirectional RNNs

A bidirectional RNN runs two RNNs over the sequence — one forward, one backward — and concatenates their hidden states. This allows each position to attend to both past and future context. Not the same as looking at the future during inference — the full sequence must already be available (not suitable for real-time generation).

7. LSTMs and GRUs

The Long-Range Dependency Problem

Simple RNNs struggle to remember events from many time steps back. In language, we often need to remember a distant context: "a bracket opened 50 words ago — I still need to close it." Gating mechanisms address this.

LSTM (Long Short-Term Memory — Hochreiter & Schmidhuber, 1997)

Two values pass between time steps: the hidden state \(h_t\) (short-term memory) and the cell state \(C_t\) (long-term memory highway). Three gates control information flow:
GateSymbolFunction
Forget gate\(f_t\)Decides what fraction of the previous cell state to discard (sigmoid → 0 to 1)
Input gate\(i_t\)Decides which new information to write to the cell state
Output gate\(o_t\)Decides what part of the cell state to expose as the hidden state

GRU (Gated Recurrent Unit — Cho et al., 2014)

Simplification of LSTM: merges forget and input gates into a single update gate and eliminates the separate cell state. Only one value passes between time steps.
LSTMGRU
Gates3 (forget, input, output)2 (update, reset)
Passed values2 (\(h_t\) and \(C_t\))1 (\(h_t\))
ParametersMoreFewer
Training speedSlowerFaster
Small data performanceCan overfit more easilyOften better with less data
Long-range memoryTheoretically betterSlightly weaker
⚠ In practice, GRUs and LSTMs perform similarly across many tasks. The recommendation is to try both — GRUs are a reasonable starting default due to lower computational cost.

8. Sequence-to-Sequence Models & Attention

Seq2Seq Architecture

An encoder RNN/LSTM compresses the entire input sequence into a fixed-length context vector. A decoder RNN/LSTM is initialised with this vector and generates the output sequence one token at a time. Used for machine translation, text summarisation, dialogue.
⚠ The fixed-length context vector is a bottleneck: for long input sequences, it cannot carry all necessary information. Performance on long sequences degrades significantly.

Attention Mechanism (Bahdanau, 2015)

Instead of compressing all encoder information into one vector, attention allows the decoder to selectively focus on different encoder hidden states at each decoding step. The decoder computes a score for each encoder hidden state, softmaxes the scores into weights, and takes a weighted sum of encoder states as the dynamic context vector.
Softmaxed attention score: \(\text{Softmax}\!\left(\frac{Q^T K}{\sqrt{n}}\right)\)    Weighted value: \(\text{score} \times V\)

9. Transformers

Attention is All You Need (Vaswani et al., 2017). The Transformer replaces recurrence entirely with self-attention. Q, K, and V all come from the same input sequence — each token attends to every other token simultaneously. This enables full parallelism during training (unlike RNNs which are sequential).

Transformer Architecture (Decoder-Only — GPT style)

  1. Token embedding: Map each input token to an N-dimensional embedding vector.
  2. Positional encoding: Add a position-dependent vector to inject word order information (self-attention itself is permutation-invariant).
  3. N Decoder blocks: each containing (a) Masked Multi-Head Self-Attention, (b) Add & Norm (residual connection + layer normalisation), (c) Feed-Forward Network, (d) Add & Norm.
  4. Linear + Softmax head: Project final representations to vocabulary logits: \(\text{logits} = X W_{vocab}\).

Self-Attention Mechanism

\[Z = \text{Softmax}\!\left(\frac{Q K^T}{\sqrt{d_k}}\right) V\] where \(Q = X W^Q\), \(K = X W^K\), \(V = X W^V\) are linear projections of the same input \(X\).
The attention matrix is masked (lower-triangular) so each token can only attend to previous tokens. This causal masking enables autoregressive generation at inference time.

Multi-Head Attention

Run h parallel attention heads, each with independent WQ, WK, WV matrices. Concatenate all h output matrices and project with WO. Multiple heads allow the model to attend to different aspects of context simultaneously (e.g., syntactic vs. semantic relationships).

Positional Encoding

Self-attention is permutation-invariant — it sees a set, not a sequence. Positional encodings (sinusoidal in the original paper, or learned in GPT) are added to token embeddings to inject position information.

GPT and RLHF

GPT models are decoder-only Transformers pretrained on next-token prediction. Modern improvements include Byte Pair Encoding (BPE) tokenisation, sparse attention, better positional encodings, Mixture of Experts (MoE), and reasoning tokens. RLHF (Reinforcement Learning from Human Feedback) fine-tunes the model to align with human preferences — the basis of InstructGPT and ChatGPT.

Transformer vs. RNN: The Complexity Trade-off

TransformerRNN/LSTM
Training parallelismFull (all tokens processed simultaneously)Sequential — cannot parallelise across time
Inference complexityO(L²) — must re-attend to full sequence per tokenO(L) — only needs previous hidden state
Long-range dependenciesExcellent — direct token-to-token attentionWeak — gradients vanish over long sequences
Context windowFixed (but very large: 128K+ tokens in recent models)Theoretically infinite; practically limited by gradient issues

Non-Transformer Alternatives

State Space Models (SSMs) like Mamba address the O(L²) attention bottleneck by recasting sequence modelling as a linear recurrence — O(L) inference, parallelisable training. xLSTM revisits LSTM with modern improvements. Diffusion LLMs apply denoising diffusion to text but have historically lagged transformers in quality.
