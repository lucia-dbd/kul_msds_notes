1. Supervised Learning – Recap

Core idea: You have a labelled dataset. The goal is to learn a mapping from features to a target so predictions can be made on unseen data.

Task Types

TaskTarget typeExamples
Binary classificationCategorical (2 classes)Churn yes/no, fraud yes/no
Multiclass classificationCategorical (>2)Product category, sentiment
Ordinal classificationOrdered categoricalCredit ratings AAA–D
Multilabel classificationMultiple binary outputsTag assignment
RegressionContinuousPrice prediction, LTV
⚠ Defining your target carefully matters: The same business problem can be cast as regression, classification, or ordinal classification. Each framing has different implications for model choice, evaluation, and calibration.

Most tabular modeling techniques assume a single feature matrix as input — relational and time-series data must be aggregated/featurized first.

2. Data Preprocessing

Data Construction & Selection

  • Merge data sources; resolve aggregation levels (household vs. individual)
  • Beware of future variables: variables that are only available after the outcome — this constitutes data leakage
  • Set aside a hold-out test set as early as possible
  • Trade-off: large historical window (more data) vs. recent window (more relevant)

Data Types

Master data, transactional data, external data (social media, macroeconomic, weather), and open data. Also distinguish: tabular vs. imagery vs. time series; small vs. big data; structured vs. unstructured.

Exploratory Data Analysis (EDA)

Visual analytics with boxplots, scatter plots, histograms, correlation plots. Tools: pandas-profiling, AutoViz, SweetVIZ. The Anscombe quartet illustrates why summary statistics alone are insufficient.

Data Cleaning

  • Fix consistency issues (e.g., "K.U.L.", "KULeuven" → unified form)
  • Unify representations (Male / Man / MAN → M)
  • Remove or flag future/leaking variables
  • Duplicate rows: can be valid or invalid — treat accordingly

3. Missing Values & Outliers

Missing Values

Distinguish MCAR (missing at random) from MNAR (missing not at random, e.g., age field blank because refused to disclose). The treatment differs: MNAR carries information.
StrategyWhen to useRisk
Delete row/columnVery high missingness rateLoss of data
Impute with meanNormal distribution, MCARDistorts variance
Impute with median/modeSkewed or categoricalLess distortion than mean
Model-based imputationComplex patternsExpensive, rarely worth it
Add missingness indicatorWhen absence itself is informativeAdds dimensionality
⚠ Production alert: Imputation rules learned on training data must be frozen and applied identically to validation and production data. Never recompute the median on new data — it becomes part of the model pipeline.

Outliers

Detection: histograms, z-scores, boxplots. Outliers can be valid (a genuine high-value customer) or invalid (data entry error).

Treatment options: (1) treat as missing if invalid; (2) keep as-is if valid and technique is robust; (3) truncate / cap; (4) categorize the feature. Note: some tasks (fraud detection) make outlier detection the entire goal.

4. Transformations & Encodings

Standardization vs. Normalization

Standardization: \( x_{new} = \dfrac{x - \mu}{\sigma} \)     Normalization: \( x_{new} = \dfrac{x - x_{min}}{x_{max} - x_{min}} \)
Standardization is required for distance-based methods (K-NN, SVM, neural nets, regularized regression). Decision trees are invariant to monotone transformations — scaling is useless for them.

Categorical Encoding Summary

MethodIdeaCaveat
Integer encodingMap categories to 1, 2, 3…Implies ordinal relationship — usually wrong
One-hot (dummy)Binary indicator per categoryDrop one column to avoid multicollinearity; curse of dimensionality with many levels
Binary encodingInteger then convert to binary bitsMore compact but less interpretable
Odds-based / WoEReplace category by log-odds w.r.t. targetUses target → must be done after train/test split
Frequency encodingReplace category by its count in training dataLoses granular differences; same rule must apply in production
EmbeddingsLearned dense vectorsNeeds enough data; mostly from deep learning

Weights of Evidence (WoE)

\( WoE_{cat} = \ln\!\left(\dfrac{p_{c1,cat}}{p_{c2,cat}}\right) \) where \( p_{c1,cat} \) = share of class-1 instances in that category.
WoE > 0 → category favours class 1. Information Value (IV) = \(\sum (p_G - p_B) \times WoE\). IV > 0.1 signals a useful predictor. WoE encodes a monotonic relationship to the target.
⚠ Fewer instances per category → less stable WoE. Apply Laplace smoothing to avoid extreme values from rare categories.

Mathematical Transformations

Log, square root, Box-Cox, Yeo-Johnson power transforms — used to induce linearity or approximate normality. Interaction variables \( x_1 \times x_2 \) capture joint effects absent from marginals.

Categorization (Binning)

Equal-width vs. equal-frequency binning. Useful for: outlier treatment, improving interpretability, reducing dimensionality, injecting non-linearities into linear models.

Ordinal Encoding

Thermometer coding: ordinal category C gets a vector of 1s up to its rank position. Percentile coding: assign the cumulative frequency as a continuous value.

5. Feature Engineering

"The aim of feature engineering is to transform dataset variables into features to help analytical models achieve better performance in terms of predictive performance, interpretability, or both."

Any domain knowledge that helps a human understand the data can usually be encoded as a feature. Most models are relatively "dumb" — smart features compound gains across all model types.

RFM Features

Recency, Frequency, Monetary — classic in marketing and fraud analytics. Recency can be modelled with exponential decay: \( recency = e^{-\gamma t} \).

Time & Date Features

  • Time is periodic — do not compute arithmetic mean of timestamps. Use sin/cos transforms or the von Mises distribution.
  • Convert raw dates to: days since event, quarter, month, week, day-of-week, is_weekend, is_holiday.

Trend & Window Features

Absolute trend: \( F_t - F_{t-x} \)     Relative trend: \( \dfrac{F_t - F_{t-x}}{F_{t-x}} \)
⚠ Watch for zero denominators in relative trends. Applying higher weight on recent values (weighted windows) is often beneficial.

Relational Data Featurization

Denormalization: merge normalized tables into a single feature matrix, aggregating child table rows. Tools: dm (R), skrub, featuretools (automated feature engineering).

Feature Selection

  • Filter methods: variance threshold, chi-square, information gain, IV, correlation
  • Wrapper methods: forward/backward/stepwise selection (use with caution — see Harrell critique)
  • Embedded methods: Lasso (L1), tree-based importance, regularization
  • Dimensionality reduction: PCA, t-SNE, UMAP
⚠ Stepwise selection on the same dataset used for confirmation leads to biased coefficients, inflated R², and invalid p-values. Always use a proper train/validation/test setup.

6. (Logistic) Regression

Linear Regression

\( y = \beta_0 + \beta_1 x_1 + \cdots + \beta_p x_p + \epsilon, \quad \epsilon \sim \mathcal{N}(0,\sigma) \)

Parameters are estimated by minimising the Sum of Squared Errors (SSE) — the OLS criterion. SSE is convex and fully differentiable → unique closed-form solution when \(X\) has full rank. For large data, gradient descent is preferred (closed form is \(O(p^3)\)).

Logistic Regression

\( P(y=1 | \mathbf{x}) = \dfrac{1}{1 + e^{-(\beta_0 + \beta_1 x_1 + \cdots)}} \)
Output is a probability ∈ (0,1). The logit (log-odds) link makes the model linear in the parameters. A one-unit increase in \(x_i\) multiplies the odds by \(e^{\beta_i}\) (the odds ratio).

Loss function: Cross-entropy (log loss): \( -[y\log p + (1-y)\log(1-p)] \). Not MSE — binary targets violate OLS assumptions.

Doubling amount for feature \(x_i\): \( \log(2)/\beta_i \) — the change required to double the odds of the outcome.

Properties & Limitations

StrengthLimitation
Interpretable coefficients & odds ratiosLinear decision boundary only
Well-calibrated probabilitiesSensitive to outliers & correlated features
Statistical rigor (p-values, CIs)Needs dummy encoding for categoricals
Fast to trainCurse of dimensionality

Extensions

Multinomial logistic regression: K classes → K−1 binary logistic models. Ordinal logistic regression (proportional odds model): one set of coefficients shared across K−1 intercept thresholds. PCR / PLS: apply PCA (or PLS) before regression to handle multicollinearity. LOESS / GAMs: non-parametric smoothers for non-linear relationships.

⚠ TLS (Total Least Squares) minimizes orthogonal distance — appropriate when both x and y contain measurement error. But predicting y from x using TLS can yield worse vertical errors than OLS.

7. Regularization

Regularization penalizes large coefficient magnitudes to prevent overfitting and improve generalization. It constrains rather than reduces the number of parameters.
Ridge (L2): \( \min_\beta \sum(y_i - \hat y_i)^2 + \lambda \sum_j \beta_j^2 \)
Lasso (L1): \( \min_\beta \sum(y_i - \hat y_i)^2 + \lambda \sum_j |\beta_j| \)
Elastic Net: \( \min_\beta \sum(y_i - \hat y_i)^2 + \lambda_1 \sum_j |\beta_j| + \lambda_2 \sum_j \beta_j^2 \)
Ridge (L2)Lasso (L1)Elastic Net
Coefficients → 0?No (shrinks toward 0)Yes (exact zeros)Yes (sparse)
Variable selectionNoYes, built-inYes
Correlated featuresDistributes weightPicks one arbitrarilyGroups them
λ tuningCross-validationCross-validationGrid search on λ₁, λ₂
⚠ Normalize features before regularization. If features are on different scales, the penalty term will disproportionately shrink coefficients of large-scale features.

The intercept \(\beta_0\) is never penalized. Regularization extends naturally to logistic regression, SVMs, and neural networks (L2 = "weight decay").

8. Decision Trees

Decision trees partition the feature space recursively using axis-aligned splits, assigning a class label or regression value to each leaf. They handle non-linearities and interaction effects naturally.

Impurity Measures

Entropy: \( H(S) = -\sum_{x \in X} p(x)\log_2 p(x) \)

Gini: \( Gini(S) = 1 - \sum_{x \in X} p(x)^2 \)

Information Gain: \( IG(A,S) = H(S) - \sum_{t \in T} p(t) H(t) \)

Entropy and Gini produce similar results. Gini is slightly faster to compute and slightly preferred for continuous splits. Classification error is too coarse for split selection.

Algorithms

AlgorithmKey FeaturesLimitations
ID3Categorical only, max depth growth, entropy + IGNo continuous vars, no pruning, severe overfitting
C4.5Continuous splits (binary threshold search), handles missing values, gain ratio, pruningSlower than CART
CARTBinary splits always, Gini for classification, SSE for regression; pruning via cost-complexity—

Continuous Splits

For a continuous feature, only distinct observed values in training are candidate thresholds. Each threshold creates a binary split (≤ vs. >). Binary splits on categoricals are also possible (avoids IG bias toward multi-way splits).

Overfitting Prevention

  • Early stopping: minimum instances per leaf, maximum depth, validation set monitoring
  • Pruning: grow full tree, then merge leaves with negligible gain (cost-complexity pruning governed by complexity parameter α)
⚠ Deep trees ≠ always overfitting. Shallow trees ≠ not overfitting. Evaluate on held-out data. Fully-grown trees have pure leaves → poor probability estimates. Pruned/stopped trees give leaf-level proportions that serve as (uncalibrated) probabilities.

Regression Trees (CART)

Leaf prediction = mean of target values. Split criterion: minimize within-group variance (equivalent to maximizing between-group variance), i.e., minimize SSE across child nodes. Regression trees typically need greater depth than classification trees.

Properties

AdvantageDisadvantage
Handles non-linearities & interactions nativelyUnstable — small data change → different tree
Robust to outliers & monotone transformsPoor calibration (probabilities)
No scaling neededLinear relationships approximated as step function
Highly interpretable (IF-THEN rules)Greedy — no guaranteed global optimum

9. K-Nearest Neighbors (K-NN)

"The data is the model." K-NN stores the entire training set and classifies/regresses new instances based on the K most similar training examples (by distance).
  • Classification: majority vote among K neighbors
  • Regression: weighted or unweighted average (weights ∝ 1/distance)
  • Requires normalization/standardization — all distance-based methods are scale-sensitive
  • K is a hyperparameter; dynamic K-values and custom distance functions are possible

Lazy Learner Properties

AdvantageDisadvantage
No training phase (trivially easy)Entire dataset must be stored and searched at inference
Naturally handles multiclassSlow at prediction time (O(n·d))
Surprisingly good with large dataSensitive to noisy features and choice of K
Easy to extend (custom distances, weights)No interpretable model output (no formula/tree)
