1. Generalization & Evaluation Philosophy

Core principle: Training performance is trivially perfect for sufficiently complex models (fully-grown tree, K-NN k=1, a database). What matters is performance on unseen data. The goal is to make the test set as challenging as possible — not to maximize the test score by repeated reuse.

Data Split Protocol

  • Train set — fit all model parameters and preprocessing rules
  • Validation set / CV folds — hyperparameter tuning and model selection
  • Test set (hold-out) — evaluated exactly once, at the very end
  • The split must happen before any preprocessing or featurization step
⚠ Out-of-time validation is more realistic for temporal data. Even repeated small parameter adjustments on the same validation set constitute hidden overtraining. If scores are suspiciously good, check for target leakage.

Stratified split: preserves the same class proportions in both train and test — critical under imbalance.

All confusion-matrix-derived metrics depend on the chosen classification threshold. Shifting the threshold changes TP, FP, TN, FN — and therefore every metric derived from them.

Core Formulae

\(\text{Accuracy} = \dfrac{TP+TN}{TP+TN+FP+FN}\)

\(\text{Recall (Sensitivity)} = \dfrac{TP}{TP+FN}\)  —  "How many positives did we catch?"

\(\text{Precision} = \dfrac{TP}{TP+FP}\)  —  "How many predicted positives are correct?"

\(\text{Specificity} = \dfrac{TN}{TN+FP}\)     \(\text{Balanced Accuracy} = \dfrac{\text{Recall}+\text{Specificity}}{2}\)

\(F_1 = 2\cdot\dfrac{\text{Precision}\times\text{Recall}}{\text{Precision}+\text{Recall}}\)
MetricBest when…Pitfall
AccuracyBalanced classes, equal error costsMisleading under imbalance — 99% accuracy from majority-class prediction
RecallMissing a positive is very costly (disease, fraud)Maximized trivially by predicting everything positive
PrecisionFalse alarms are costly (spam filter, automation)Maximized trivially by being very conservative
F1Imbalanced classes, both error types matterHarmonic mean — very sensitive to the weaker of the two
AUC-ROCThreshold-independent comparison, balanced dataOptimistic under heavy imbalance
AUC-PRHeavily imbalanced datasetsMore sensitive to positive class performance
⚠ Never rely on accuracy alone under class imbalance. A model predicting only the majority class achieves 99% accuracy when positives are 1% of data — yet catches zero true positives.

3. Cost-Sensitive Classification

Different errors carry different business costs. A cost matrix makes these explicit:

Actual NegativeActual Positive
Predicted NegativeC(0,0) = 0C(0,1) = cost of False Negative
Predicted PositiveC(1,0) = cost of False PositiveC(1,1) = 0

Expected Loss & Cost-Sensitive Threshold (TCS)

\(\ell(x,1) = p(0|x)\cdot C(1,0)\)     \(\ell(x,0) = p(1|x)\cdot C(0,1)\)

Classify as positive when \(\ell(x,1) < \ell(x,0)\)

\(T_{CS} = \dfrac{C(1,0)-C(0,0)}{C(1,0)-C(0,0)+C(0,1)-C(1,1)}\)
With symmetric unit costs (C(1,0)=C(0,1)=1, C(0,0)=C(1,1)=0): TCS = 0.5. High FN cost → TCS is pushed down, making the classifier more aggressive at flagging positives.
Example: C(0,1)=5, C(1,0)=1 → TCS = 1/6 ≈ 0.167. A model scoring p(1|x)=0.22 exceeds the threshold and should be classified as positive.
Key insight: Oversampling/undersampling to a 1:1 class ratio is mathematically equivalent to using a cost matrix built from the inverse class distribution. They bias the classifier identically.

4. Sampling for Class Imbalance

MethodIdeaProsCons
Oversampling (upsampling)Duplicate minority class instancesNo data lossCan overfit to duplicates
Undersampling (downsampling)Remove majority class instancesFaster trainingDiscards useful data
SMOTESynthesize new minority instances by interpolating between K nearest neighborsCreates diverse synthetic dataCan create unrealistic instances; not magic
CombinedSMOTE minority + undersample majorityFlexible controlTwo hyperparameters

SMOTE Algorithm

  1. For each minority instance, find its K nearest minority-class neighbors
  2. Pick one neighbor randomly; generate a synthetic point interpolated along the line segment
  3. Repeat until target balance is achieved
⚠ Critical rules: (1) Sampling applies only to the training set — the test set must remain untouched. (2) SMOTE does not invent hidden or future patterns. (3) For tree-based ensembles and deep learning, cost-sensitive loss modification is often better. (4) Accuracy on a resampled training set will appear lower than "always-majority-class" — this is correct and expected.

5. ROC Curve, AUC, and Separation Metrics

The ROC curve plots Sensitivity (TPR) vs. 1 − Specificity (FPR) across all possible thresholds. A perfect classifier occupies the top-left corner. AUC = area under this curve.
AUCInterpretation
1.0Perfect discrimination
0.9–1.0Excellent
0.7–0.9Good
0.5Random — no better than chance
<0.5Worse than random (usually a sign of error)

Probabilistic interpretation (Hanley & McNeil, 1983): AUC = P(score of random positive > score of random negative). It is threshold-independent.

Other Separation Metrics

\(KS = \max_s |P(s|y=1) - P(s|y=0)|\)    (max distance between class score CDFs)

\(M = \dfrac{|\mu_p - \mu_n|}{\sigma}\)    (Mahalanobis distance, accounts for spread)

\(D = \dfrac{(\mu_p-\mu_n)^2}{\frac{1}{2}(\sigma_p^2+\sigma_n^2)}\)    (Divergence measure)

\(AR = 2 \times AUC - 1\)    (Accuracy Ratio from CAP curve)

H-index (Hand, 2009): addresses AUC's theoretical incoherence — AUC implicitly uses different misclassification cost distributions for different classifiers, making comparisons potentially misleading when ROC curves cross.

6. Lift, CAP, and Ranked-List Metrics

Lift at n% = (fraction of positives in top n% by model) ÷ (fraction of positives in top n% by random). Lift = 1 means the model does no better than random selection.

CAP (Cumulative Accuracy Profile) / Lorenz / Power curve: sort by predicted score descending; plot cumulative % of positives captured vs. % of population contacted.

Precision/Recall at N: evaluate only among the top-N ranked predictions. Critical in settings where a fixed-size shortlist is delivered (fraud alerts to investigators, top-K recommendations).

Example: If 5% of the population are positives and your model in the top 10% captures 40% of all positives, lift = (40%/10%) ÷ (5%/100%) = 4 ÷ 5 = ... actually: lift = (40% positives in top 10%) / (5% base rate × 10% population) = 40/5 = 8. The model is 8× more efficient than random at the top decile.

8. Cross-Validation & Hyperparameter Tuning

Cross-validation is for tuning; the test set is for final evaluation. Using the test set during tuning — even once — permanently contaminates it.

k-Fold Cross-Validation Protocol

  1. Split training data into k equal folds
  2. Train on k−1 folds; evaluate on the remaining fold
  3. Rotate the held-out fold k times
  4. Average performance across all k folds → stable estimate for hyperparameter comparison

CV produces a pessimistically biased estimate because each fold uses less training data than the full set. Leave-one-out CV is approximately unbiased but expensive.

Key Rules

  • Preprocessing (imputation, WoE encoding, scaling) must be fitted inside each CV fold — never pre-computed on all data before CV begins
  • Too many hyperparameter combinations on the same CV scheme leads to data dredging
  • After tuning: retrain with optimal params on the full training set; evaluate once on the held-out test set
  • Nested CV: outer loop = generalization estimate; inner loop = hyperparameter tuning

9. Multiclass & Multilabel Classification

Multiclass Strategies

StrategyHow it worksClassifiers needed
One-vs-All (OvR)Each class against all others; assign highest posterior probabilityK
One-vs-One (OvO)Every pair of classes; majority vote across all pairwise outcomesK(K−1)/2

ROC requires one curve per class (OvR decomposition); then macro- or weighted-average across curves.

Multilabel Strategies

  • Binary relevance: one independent binary classifier per label — simple but ignores label correlations
  • Classifier chaining: predictions of earlier classifiers become features of later ones — captures label dependencies
  • Label powerset: each unique label combination is a class — exponential explosion of classes

Evaluation metrics: Hamming loss, Jaccard index, instance-level and label-level precision/recall adapted for multiple labels.

10. Interpretability Techniques

White-box models (logistic regression, decision trees, rule sets) are interpretable by design. Black-box models (ensembles, deep learning) require post-hoc techniques. Two dimensions: scope (global vs. local/instance) and specificity (model-specific vs. model-agnostic).

Feature Importance

MethodAgnostic?Key propertyKey limitation
MDI (Mean Decrease Impurity)No (trees)Fast, built-in for forestsBiased toward high-cardinality features; inflated when overfitting
Permutation importanceYesNo retraining; valid on test setCorrelated features share importance; breaks interaction effects
LOFO (Drop-feature)YesMost preciseRequires retraining per feature — very slow
⚠ Correlated features share permutation importance. Permuting one correlated feature while keeping the other intact underestimates true importance. Permute groups of correlated features together for accurate joint importance.
Use test set importance to understand generalization drivers. Use train set importance to understand how the model actually used each feature during training.

Partial Dependence Plots (PDP)

Shows the average marginal effect of a feature on the model's output, averaging over the distribution of all other features. Two approaches: (1) impute others with median/mode; (2) average predictions across real instances from training data.

⚠ PDPs use a ceteris paribus assumption. A flat PDP does not mean a feature is unimportant — it may be active in interactions that cancel out in the average. If the raw data binning shows an effect but the PDP is flat, interaction effects are present.

ICE (Individual Conditional Expectation) Plots

Extension of PDP: one prediction trajectory per instance instead of just the average. When ICE lines diverge or cross while the PDP is flat, this reveals heterogeneous interaction effects. Centering the lines at a reference feature value makes deviations from the average effect visible.

LIME

Local, instance-level, model-agnostic explanation. Perturb the instance → get black-box predictions → fit a simple weighted local model (Lasso or shallow tree) on the perturbed data → use local coefficients as explanation. Works for tabular data, text (remove words), and images (blank superpixels).

⚠ LIME is unstable: results depend on the kernel bandwidth, distance measure, and Lasso regularization. This instability is why SHAP has largely replaced it in production settings.

11. Shapley Values & SHAP

Shapley values from cooperative game theory fairly attribute team outcomes to individual players based on their average marginal contribution across all possible team formations. In ML: features are players, predictions are payouts.
\(\phi_j = \sum_{S \subseteq \{x_1,\ldots,x_p\}\setminus\{x_j\}} \dfrac{|S|!\,(p-|S|-1)!}{p!}\bigl[v(S\cup\{x_j\})-v(S)\bigr]\)

Efficiency axiom: \(\sum_j \phi_j = \hat{f}(x) - \mathbb{E}[\hat{f}(X)]\) — Shapley values partition the deviation from the baseline prediction exactly.

Monte Carlo Approximation

\(\hat\phi_j \approx \dfrac{1}{M}\sum_{m=1}^M\bigl[\hat f(x^m_{+j}) - \hat f(x^m_{-j})\bigr]\)

For each of M permutations: draw a random reference instance z; construct two instances — one with x's value for feature j, one with z's value; the other features are randomly mixed from x and z. Difference in predictions = j's marginal contribution for that permutation.

Example: baseline = 0.10. Age=65 → +0.40; sex=F → −0.30; bp=180 → +0.10; bmi=40 → +0.10. Final prediction = 0.10 + 0.40 − 0.30 + 0.10 + 0.10 = 0.40.

SHAP Visualizations

PlotScopeWhat it shows

SHAP is the most widely used instance-level explanation method in industry. It unifies global importance, partial dependence, and instance-level explanations in one theoretically grounded framework.
⚠ SHAP values reflect model attribution, not causal effects. Correlated features share SHAP values. Do not interpret SHAP as "removing this feature would change the prediction by φ_j" — Shapley values are defined as average marginal contributions, not as interventional effects.

Production Monitoring

Track over time: feature distribution drift (PSI), prediction score distribution shift, outcome-based metrics on newly labelled batches, and calibration drift. Set automated thresholds to trigger retraining. ML models are high-maintenance systems — monitoring is not optional.
