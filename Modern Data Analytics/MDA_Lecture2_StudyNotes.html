1. The Python Package Ecosystem

Python's power for data science comes not from the base language alone, but from a rich ecosystem of packages developed by the open-source community and companies. These packages implement commonly needed behaviors so you don't have to start from scratch.

Key insight: Packages serve two purposes — (1) code organisation within a project, and (2) sharing and reusing code across the broader developer community via repositories like PyPI.

Installing and importing packages

Packages are distributed via PyPI (Python Package Index) and installed with pip:

pip install pandas          # Step 1: install
import pandas as pd         # Step 2: import with alias
⚠ Important: When you import a module, its top-level code is executed immediately. This can have side effects — be mindful of what code lives at module level vs inside functions.

Packages are installed into your environment's site-packages folder (e.g., lib/python3.10/site-packages/pandas/). When you write from pandas import DataFrame, Python locates the DataFrame class in that folder.

2. Code Organisation: Modules & Packages

As Python projects grow, organising code becomes critical. OOP lets you group related functionality into classes; modules and packages let you group related classes into files and folders.

Modules

Definition: A module is any .py file containing valid Python code. The filename (without .py) becomes the module name.

Example: A file models.py containing a LinearRegression class becomes the models module.

Importing modules — three patterns

SyntaxEffectAccess
import <module>Imports entire modulemodule.ClassName()
from <module> import <Class>Imports specific class(es)ClassName() directly
import pandas as pdImports with aliaspd.DataFrame()
⚠ Directory constraint: By default, the module file and the script using it must be in the same directory for a simple import to work.

Packages

When a project has many modules, Python lets you organise them into a package — a hierarchical folder structure. A package named mda can contain subpackages like classification and regression, each with their own models.py.

Example structure:
mda/classification/models.py → LogisticRegression
mda/regression/models.py → LinearRegression

Import with dot notation:
from mda.regression.models import LinearRegression
from mda.classification.models import LogisticRegression

The __init__.py file

Adding an __init__.py file to a package folder allows you to define what gets imported when the package itself is imported. This simplifies imports for users of your package:

# mda/__init__.py
from .regression.models import LinearRegression
from .classification.models import LogisticRegression

# User can now write:
from mda import LinearRegression
from mda import LogisticRegression
The __init__.py is executed when the package is imported — put only necessary setup code here, not heavy computation.

3. NumPy

NumPy introduces the ndarray — a fundamental data structure for numerical computing that dramatically outperforms Python's built-in lists in both memory usage and computational speed.

Array dimensions

DimensionShape exampleUse case
1D array (vector)(4,)A single feature column
2D array (matrix)(2, 3)Rows × Columns of data
3D array (tensor)(4, 3, 2)Image data (height, width, channels)

Why NumPy outperforms Python lists

NumPy achieves two major performance gains:

(1) Memory efficiency — storage: A Python list stores pointers to objects scattered across memory. A NumPy array stores all values contiguously in a single data buffer with a fixed type. This eliminates pointer indirection and reduces memory fragmentation.
(2) Memory efficiency — operations: NumPy offers two strategies when transforming arrays:
  • Copy (arr[[0,2,4]]): Creates a new data buffer. Safe from side effects, but uses more memory.
  • View (arr[::2]): Reuses the original data buffer with new metadata (shape, strides). Memory-efficient, but modifying the view modifies the original.

Memory layout: strides

NumPy stores 2D arrays in row-major order (C order) by default — rows are stored consecutively. Column-major order (Fortran order) stores columns consecutively. Slicing can change the stride (step between elements in memory), which may affect contiguity.

Metadata of a NumPy array: Length · Type · Shape · Strides
The data buffer contains the actual values. Memory is always 1D — the shape/stride metadata creates the illusion of 2D/3D structure.
⚠ Common mistake: "Memory is 2D" — it is not. A 2D NumPy array is still stored as a flat 1D sequence in memory. The strides tell Python how many bytes to jump to reach the next row or column.

4. Pandas

Pandas is a structured abstraction built on top of NumPy. It inherits NumPy's memory model while adding support for heterogeneous data types, labeled axes (indices and column names), and alignment.

NumPy vs pandas: key differences

FeatureNumPyPandas
Data typesHomogeneous (all same type)Heterogeneous (columns can differ)
LabelingNo labeling mechanismLabeled axes (index + column names)
Row/column identityNo conceptAlignment at row/column level
Memory modelNumPy ndarrayInherits NumPy memory model
DataFrame structure: A DataFrame is a collection of Series objects. Each Series is a 1D array (a column). All columns share the same index. Columns may have different dtypes. This is analogous to a 2D NumPy array but with labeled axes.

Indexing in pandas

In NumPy, elements are accessed by their integer position. Pandas adds label-based access:

df.loc[:, ['First', 'Last', 'Math']]   # label-based
df.iloc[0, 0] = 100                    # position-based

Copy-on-Write (pandas ≥ 3.0)

In older pandas, a "view" of a DataFrame shared the underlying data buffer. Modifying the view would modify the original — leading to the infamous SettingWithCopyWarning.

Copy-on-Write guarantee: Any DataFrame or Series derived from another always behaves as a copy. Under the hood, pandas uses a Block Reference Tracker (BRT) to lazily decide when to actually copy data — copying only when a write operation occurs and the block is shared. This balances usability with memory efficiency.
Example of the old problem:
grades = df["grade"] — this was a view
grades.iloc[0] = "E" — this would silently modify df too!

With CoW (pandas ≥ 3.0), grades behaves as an independent copy — df is not affected.

Copy-on-Write write mechanism

When you perform a write operation (df2.iloc[0,0] = 100):

  1. Check: is the underlying block referenced by another DataFrame?
  2. If yes: create a copy of the data block; create a new BRT for this DataFrame.
  3. If no: update the data block in-place (no copy needed).

Pandas extensions: GeoPandas

GeoPandas extends pandas by adding a geometry column to DataFrames, enabling geospatial analysis. It inherits the DataFrame interface fully — it's not just syntax-compatible, it actually inherits from DataFrame in the class hierarchy.

5. Data Visualization

Choosing the right visualization library depends on the use case:

LibraryBest forInteractivity
matplotlibStatic 2D plots (line, bar, scatter, histogram)None (static)
PlotlyInteractive charts with hover, zoom, pan, selectionHigh (JS-based)
AltairComplex, layered declarative visualizationsMedium

Plotly — two interfaces

plotly.express (px): High-level interface. Takes a pandas DataFrame as input, auto-infers plot settings. Best for quickly creating common chart types with minimal code.
plotly.graph_objects (go): Low-level interface. Full control over individual plot objects (traces, axes, layouts). More verbose but more powerful and flexible.

Typical plotly.graph_objects workflow

import plotly.graph_objects as go
fig = go.Figure()                        # 1. Initialize empty figure
fig.add_trace(go.Scatter(...))           # 2. Add traces (layers)
fig.update_traces(mode='markers', ...)  # 3. Style all traces
fig.update_layout(title='...')           # 4. Set global layout
fig.show()                               # 5. Render
⚠ Key difference from matplotlib: In plotly, you always call methods on the figure object. In matplotlib, you often call functions on the module directly. Plotly's object must be referenced explicitly (fig.add_trace, not just add_trace).

Dashboarding tools

For production dashboards, the ecosystem includes: Plotly Dash, Streamlit, Tableau, Power BI, Looker, Grafana, and others. Plotly Dash is highlighted in the course as it integrates directly with Python and Plotly charts.

6. Publishing Packages on PyPI

Publishing your own package to PyPI follows a 4-step process:

StepActionKey tool
1Adopt the correct file structureManual
2Test your package locally (editable install)pip install -e .
3Build the package (source + wheel)python -m build + twine check dist/*
4Upload to (Test)PyPItwine upload -r testpypi dist/*

Required file structure (minimum example)

src/mda/__init__.py — package initializer
src/mda/example.py — your module(s)
tests/dummy.py — test suite (pytest)
LICENSE — open source license (e.g. MIT)
manifest.in — files to include when building
pyproject.toml — build system + project metadata
readme.md — project description (shown on PyPI)

The pyproject.toml file

This file has two sections:

  • [build-system]: Specifies how to build (e.g., using setuptools). Transforms Python files into a distributable wheel (.whl).
  • [project]: Metadata — name, version, description, authors, license, Python requirements. These are displayed on PyPI.
⚠ The package name must be globally unique on PyPI. You cannot upload a package with a name already taken.

Build outputs

Running python -m build produces two files in dist/:

  • .whl (wheel) — used during installation by pip
  • .tar.gz — source distribution, a copy of your package code
Editable installs (pip install -e .) let you install your package locally while still being able to edit source files — no reinstallation needed after every change. Essential for development.
