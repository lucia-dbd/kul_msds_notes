1. Introduction & Motivation

Shiny for Python is an open-source Python package that creates interactive web applications directly from your Python analyses — without requiring HTML, CSS, or JavaScript knowledge. It originated from R Shiny (2012) and was ported to Python in 2022.

Core idea: "Move the water surface downwards" — expose the full depth of your analysis to an audience interactively, rather than showing only a static surface.

Deployment options

OptionDescriptionWhen to use
Cloud hostingShinyapps.io or Hugging Face SpacesNo own server needed; public/shared apps
Self-hosted (on-premise)Shiny Server (open source) or Posit Connect (enterprise)Must run inside network/VPC
Static / ShinyLiveRuns Python logic in the browser via WebAssemblyNo server at all; free hosting; infinitely scalable
ShinyLive ≠ full Shiny: Only apps that can run entirely client-side qualify. Heavy server-side dependencies may not work.

2. App Architecture

Every Shiny app has three components defined in app.py:

Template structure: 
from shiny import App, ui, render

app_ui = ui.page_fluid()          # UI object

def server(input, output, session):
    pass                          # Server logic

app = App(ui=app_ui, server=server)  # Combines both
ComponentRole
uiNested Python functions that assemble an HTML user interface
serverFunction with instructions to build/rebuild Python objects displayed in the UI
AppCombines ui and server into a functioning application
A Shiny app is a web page (UI) connected to a live Python session (Server). User interactions in the UI trigger Python code on the server, which updates the UI in return.

Running an app

Two methods: VS Code with the Shiny extension (recommended — supports Debug Mode with breakpoints), or the command line: shiny run --reload --launch-browser app_dir/app.py

Minimal working example: 
app_ui = ui.page_fluid(
    ui.input_numeric("n", "Sample size", 25),
    ui.output_plot("hist")
)

def server(input, output, session):
    @render.plot
    def hist():
        data = np.random.randn(input.n())
        fig, ax = plt.subplots()
        ax.hist(data, bins=10)
        return fig

3. UI Framework — Inputs, Outputs & Layout

Input widgets

Input values are reactive. They are declared with ui.input_<type>() and accessed in the server with input.<inputId>().

FunctionWidget type
ui.input_numeric()Numeric spinner
ui.input_slider()Slider (single or range)
ui.input_text() / input_text_area()Text box
ui.input_select() / input_selectize()Dropdown
ui.input_radio_buttons()Radio buttons
ui.input_checkbox() / input_checkbox_group()Checkboxes
ui.input_date() / input_date_range()Date picker
ui.input_action_button()Clickable button
ui.input_file()File upload

Output functions

ui.output_<type>() in the UI and @render.<type> in the server always work as a matched pair.

UI functionServer decoratorOutput
ui.output_plot()@render.plotMatplotlib / Seaborn figure
ui.output_data_frame()@render.data_frameInteractive data table
ui.output_text()@render.textPlain text
ui.output_ui()@render.uiDynamic HTML/UI elements
output_widget()@render_widgetipywidgets (e.g., Plotly)
ui.download_button()@render.downloadFile download

Layout & panels

Panels group elements; layout functions organize panels.

Common layout pattern: ui.page_fluid(ui.layout_sidebar(ui.sidebar(...), ui.output_plot(...)))

Navigation: ui.navset_tab(), ui.navset_pill_list(), ui.page_navbar() — all use ui.nav_panel() children.

HTML customization

The app UI is an HTML document. Shiny provides helpers: ui.HTML(), ui.div(), ui.span(), ui.h2(), and ui.tags.video() for less common tags. CSS and JS files go in the www/ subdirectory and are linked via ui.HTMLDependency().

4. Reactivity

Reactivity is the mechanism that keeps outputs synchronized with inputs automatically.

Core reactive functions

FunctionPurpose
@render.*Render reactive output (plot, text, table, etc.)
@reactive.CalcCreate a cached reactive expression reusable in multiple render blocks
@reactive.Effect / @reactive.event()Perform side effects; react only on specific event
reactive.Value()Create a mutable reactive value
reactive.isolate()Read a reactive value without registering a dependency (partial reactivity)
reactive.invalidate_later()Schedule periodic updates
@reactive.Calc — key properties:
  • Caching: computed once and reused across multiple render blocks → avoids redundant computation.
  • Invalidation: automatically re-evaluated when any upstream input changes.
  • Use it when the same reactive expression is consumed by two or more @render.* functions.
Partial reactivity pattern (App 7): Wrap inputs in reactive.isolate() inside a @reactive.Calc that also calls input.update(). The output only reacts to the action button click, not to every slider movement.
Partial reactivity example: 
@reactive.calc
def histogram_params():
    input.update()               # react to button click
    with reactive.isolate():
        bins  = input.bin()      # isolated — no dependency
        color = input.colour()
    return bins, color
Common mistake: Calling input.x() directly inside a render block registers a dependency. To read without dependency, always wrap in reactive.isolate().

5. Dynamic User Interface

Dynamic UIs allow sidebar inputs to change based on other inputs. The server generates HTML and sends it to the client via @render.ui, displayed with ui.output_ui(). Each update completely replaces the previous component.

Pattern (App 8 — dataset-dependent variable selectors): 
def get_variable_choices():
    return list(datasets[input.data1()].columns)

@render.ui
def vx():
    return ui.input_select("variable_x", "Select X", get_variable_choices())

# In UI:
# ui.output_ui("vx")
Dynamic UI is appropriate when: the choices in one input depend on the value of another input (e.g., column names depend on the selected dataset).

6. Interactive Outputs with ipywidgets

Static outputs (matplotlib plots, plain tables) can be replaced with interactive widgets via the shinywidgets package.

CategoryNotable packages
Interactive plotsplotly, altair, bokeh
Mapspydeck, ipyleaflet
Tables/gridsipydatagrid, ipysheet
3D visualizationsipyvolume, pythreejs
Integration pattern:
  1. Install: pip install shinywidgets
  2. Replace ui.output_plot("id") with output_widget("id") in the UI
  3. Replace @render.plot with @render_widget in the server
  4. Return a widget object (e.g., a Plotly figure) from the function
Note: @render_widget and output_widget() must be imported from shinywidgets, not from shiny.

7. Extension to Dashboards

The built-in Shiny UI is functional but minimal. More polished dashboards can be built by:

  • Adding custom HTML/CSS/JavaScript (flexible but time-consuming)
  • Using pre-defined dashboard templates from shiny.posit.co/templates and shiny.posit.co/py/gallery/
Dashboard components like value boxes, metric cards, and responsive grid layouts are available through Shiny's component library and community extensions.

Key design considerations

  • Use ui.layout_columns() for side-by-side elements within a panel
  • Combine ui.navset_tab() with multiple ui.nav_panel() blocks for multi-tab dashboards
  • Use ui.download_button() + @render.download for export functionality
  • ShinyLive enables zero-cost static hosting for appropriate apps
